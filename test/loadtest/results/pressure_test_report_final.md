## 术语解释

| 术语 | 全称 | 说明 |
|------|------|------|
| **RPS** | Requests Per Second | 每秒请求数，衡量服务器处理能力的核心指标。RPS越高表示服务器在单位时间内能处理的请求越多。 |
| **延迟（Latency）** | - | 从发送请求到收到响应的时间。延迟越低表示服务器响应越快。 |
| **平均延迟** | Average Latency | 所有请求延迟的平均值，反映整体响应速度。 |
| **P95延迟** | 95th Percentile Latency | 95%的请求延迟低于此值。用于评估最坏情况下的用户体验，比平均延迟更能反映真实体验。 |
| **VU** | Virtual Users | 虚拟用户数，k6模拟的并发用户数量。 |
| **成功率** | Success Rate | 成功请求数占总请求数的比例。100%表示所有请求都按预期完成。 |
| **突刺（Spike）** | - | 短时间内并发用户数急剧增加，用于测试系统应对突发流量的能力。 |

## 性能优化记录

### 已完成的优化（13项）

#### 阶段1：快速优化
1. **消除登录失败冗余DB查询** - `handleLoginFailure`接收user对象，消除重复GetByEmail查询
2. **异步发送验证邮件** - 注册时使用goroutine异步发送邮件，不阻塞响应
3. **并行化登录成功操作** - `ResetLoginAttempts`和审计日志并发执行
4. **数据库索引验证** - 确认关键索引已存在（006/007/008迁移）
5. **连接池配置优化** - DBMaxOpenConns:50→100, DBMaxIdleConns:25→50, 新增DBConnMaxIdleTime

#### 阶段2：缓存优化
6. **UserInfo接口添加缓存** - 查询结果缓存5分钟，避免重复DB查询
7. **修复Auth Middleware使用Request Context** - 替换context.Background()为r.Context()
8. **优化MemoryCache.DeletePattern性能** - 使用读锁遍历+逐个写锁删除，避免长时间持有写锁
9. **添加缓存穿透防护** - 引入golang.org/x/sync/singleflight，防止缓存击穿

#### 阶段3：高级优化
10. **MFA Recovery Code O(n) Bcrypt优化** - 使用HMAC-SHA256替代bcrypt，实现O(1)查找
11. **Rate Limiter全局锁优化** - 使用64分片锁，减少高并发下的锁竞争
12. **Redis端口可配置** - 修复硬编码:6379，支持自定义端口
13. **Redis重连逻辑** - go-redis内置自动重连机制

| 指标 | 优化前 | 优化后（预期） |

## 生产环境建议

### 实例数量

- **登录/注册**：BCRYPT_COST=12时单实例~11 RPS
- **建议部署**：2-3个实例应对高峰期
- **总容量**：~33 RPS（3实例）

### 其他建议

1. **启用Redis缓存** - UserInfo接口性能提升显著
2. **配置限流** - 生产环境启用RATE_LIMIT_REQUESTS
3. **监控告警** - 监控登录/注册延迟，超过500ms告警
4. **水平扩展** - 根据业务需求动态调整实例数量
5. **设置MFA_RECOVERY_HMAC_KEY** - 生产环境必须设置强HMAC密钥
